# Discount Code — the two-table model

## Identity

A Discount Code's field set depends entirely on its kind. **Container codes and Code PRO codes live in two SEPARATE tables with different field sets.** Fields like `max_uses`, `uses`, `date_end`, `notes` exist on **Code PRO codes only**; Container codes have a much smaller set.

A Code PRO code belongs to a `code-pro` discount. A Container code belongs to no discount: the codes are one store-wide pool, and they apply to the active discounts with `is_container = 1`.

## Aliases

- **Container code** — a code in the store-wide pool (the classic [[marketing-discounts-codes]] feature), stored in the `discount_codes` table.
- **Code PRO code** — a code under a Code PRO parent ([[marketing-discounts-code-pro]]), stored in the `discounts_code_pro` table.

## Key Attributes

### Container code (`discount_codes` table)

For codes in the store-wide pool (the classic [[marketing-discounts-codes]] feature):

| Field | What it stores | Notes |
|-------|----------------|-------|
| `code` | The redeemable string | Required and unique in the pool. Auto-generated by the platform during a batch run — 10-character uppercase alphanumeric (`A-Z` + `0-9`). The merchant cannot pick length, prefix, or character set on a batch. |
| `type` + `value` | The discount amount captured at batch generation time | Each batch run can use a different value (e.g., "1,000 codes at 10%" + "500 codes at 15%" → all 1,500 rows in the one pool, mixed values). |
| `active` | yes / no | Per-row toggle. An order does not use a code up: it stays reusable until turned off or deleted. Turning a code off stops typing it. |

**Container codes do NOT carry their own `max_uses`, `date_end`, `notes` or `conditions` columns.** Restrictions (date window, customer groups, geo zone, `max_uses`, `maxused_user`, `code_apply`, `apply_regular_price`) come from the **Container discount** the code lands on. See [[discount-stacking-cart-code-slots]].

### Code PRO code (`discounts_code_pro` table)

For codes under a Code PRO discount ([[marketing-discounts-code-pro]]) — each row carries full per-code configuration:

| Field (Code PRO only) | What it stores | Notes |
|-----------------------|----------------|-------|
| `code` | The redeemable string | Required and unique store-wide. Case-insensitive matching at checkout. The merchant typically picks the string explicitly OR generates a batch via the [[marketing-discounts-code-pro-generator|generator]]. |
| `discount_id` | FK → parent Code PRO [[discount|Discount]] | Required. |
| `value` / `type_value` | The discount amount specific to THIS code | Each Code PRO row can have a different value (e.g., one code gives 10% off, another gives 20%). |
| `conditions` | Per-code conditions | Order-over threshold, product / category / vendor / selection restriction, customer-group restriction, region restriction — all defined per-code (up to 5 conditions, surfaced via the editor UI). |
| `max_uses` / `uses` | Per-code use cap + running counter | When set, the code can be redeemed at most this many times across all customers. When `null`, unlimited. See [[discount-code-entity-usage-limits]] for the counter mechanics. |
| `maxused_user` | Per-customer use cap | It counts across the whole Code PRO campaign. |
| `date_start` / `date_end` | Per-code lifetime | When set, the code stops working at the configured time even if the parent Discount is still active. When `null`, follows the parent Discount's dates. |
| `code_format` + `code_prefix` | Barcode mode | Optional EAN-8 / EAN-13 barcode mode (see Code PRO docs for details). |
| `active` | yes / no | Per-code enable flag. |
| `force_save` | Per-code force-save | When set, the code STAYS on saved orders even after admin edits. |
| `only_customer` | Registered-users-only flag | When set, guests are excluded from this code — see [[discount-code-entity-customer-binding]]. |

Code PRO codes have INDIVIDUAL terms per code — they are independent rows with full per-code configuration. Container codes share the parent's terms.

The `notes` field (Code PRO) is for the merchant's internal annotations (e.g., "Code for the May newsletter blast"). It is never rendered on the storefront, in emails, or in customer-facing dashboards.
