# Brand settings — Slots

## Purpose

The seven fixed brand-asset slots on the Brand settings page, each with its own slot ID, backend label, recommended size, intended use, and storage backend. This is the lookup table merchants use to answer "where do I upload an SVG logo for X?" — the slot list is exhaustive and not extensible.

## Where to find it

Sidebar → Settings → **Brand settings**. The slots appear as a two-column grid (one column on mobile), each rendered as an independent card with drag-and-drop upload (see [[settings-brand-upload-flow]]).

## What the merchant can do here

- See all seven slots at once and pick the right one for their asset.
- See the per-slot recommended dimensions and accepted file formats.
- Upload one asset per slot; replace or delete independently.

## Settings & fields

The seven asset slots, in the order they appear:

| Slot ID | Backend label | Used for | Recommended size | Notes |
|---------|---------------|----------|------------------|-------|
| **main** (`main`) | "Store logo" | Storefront header (every page on the public site). | 200 × 80 px | The big one — most visible asset. Stored as a logo row with `type='logo'`. |
| **favicon** (`favicon`) | "Favicon" | Browser tab icon, bookmark icon, mobile home-screen icon. | Square, up to 240 × 240 px | Stored as a `FavIcon` row (separate model) — see [[settings-brand-favicon]] for the cache-busting side-effects. |
| **invoice** (`invoice`) | "Logo for Invoice" | PDF invoices generated by the store. | 200 × 80 px | Used only on invoice PDFs — see [[settings-invoicing]]. Independent from the storefront-header variant so the merchant can use a formal-looking variant on invoices. |
| **mail** (`mail`) | "Logo for Email" | Header of outgoing transactional emails. | 200 × 80 px | Independent from storefront / invoice variants. |
| **default_image** (`default_image`) | "Default image" | Fallback for products with no image set. | 200 × 80 px (per code; conceptually a square is more typical for product images) | Used everywhere a product image would render but the product has no image. |
| **checkout** (`checkout`) | "Store checkout logo" | Checkout page header. | 200 × 80 px | Lets the merchant use a different (often simpler) logo on checkout for trust signals — see [[settings-cart]]. |
| **og_image_url** (`og_image_url`) | "Cover image for sharing" | OpenGraph image (Facebook / Twitter / etc. share previews). | 200 × 240 px (default) | **Different storage and upload flow** — stored as a setting value (URL string), not a logo row. No preview module. See [[settings-brand-og-image]]. |

### Two storage backends behind the slots

- **Six slots** (`main`, `invoice`, `mail`, `default_image`, `checkout`, plus `favicon`) save into proper model rows: the `Logo` model for five of them (`type=<slot>`), the `FavIcon` model for the favicon. The uploaded file is stored on the platform's file storage; the row gives `getImage('150x150')` for resized thumbnail URLs.
- **One slot** (`og_image_url`) is a setting value (URL string), not a logo row. The flow is two-step — see [[settings-brand-og-image]].

This split exists because the OG image needs to be reachable via a stable public URL for Facebook / Twitter scrapers; the other logos are rendered through CloudCart's image-serving layer.

## Business rules

### `default_image` is auto-scaled to the requested thumbnail size

The "200 × 80" recommended-size copy on the `default_image` slot is misleading for the product-image use case. In practice the platform renders this asset through a per-thumbnail call that generates a CDN URL with the calling code's requested thumbnail size (e.g., 400×400 for product grids, 800×800 for product detail pages). So the merchant can safely upload a square image at 800×800 or 1000×1000 — the image-serving layer will downscale on the fly for each consumer. The "200 × 80" hint exists because the slot was originally designed for landscape brand-strip use; for the product-fallback role a square at 1:1 aspect is more appropriate.

### Seven fixed slots — neither configurable nor extensible

The slot list is fixed by the platform. The merchant cannot add a slot for, say, "PDF receipt logo" — the seven listed are the only ones the platform consumes. If a merchant asks "where do I upload an SVG logo for X?", they need to know which of the seven slots is closest in usage. See [[settings-brand-limitations]] for the rationale and other product-level fixed-design rules.

### `mail` slot consumers — no Emails-settings screen

There is no merchant-facing Emails settings screen anymore. The `mail` logo is still consumed by the transactional email rendering layer, so the slot remains active — but there is no dedicated screen to preview email branding outside the rendered transactional emails themselves.

### Slot order on the page is fixed

The grid renders slots in the order shown in the table above. The merchant cannot reorder. The two-column layout pairs `main` + `favicon` on row 1, `invoice` + `mail` on row 2, etc.

### `invoice` slot — SVG inconsistency

The modern Vue upload path accepts SVG for the `invoice` slot. The legacy upload path (no longer used by the Brand settings page) explicitly rejects SVG with *"settings.logo_image_upload_error_svg"*. Practical recommendation: use PNG or JPG for the `invoice` slot regardless, because the PDF invoicing pipeline may not render SVG correctly. See [[settings-brand-cache-and-storage]] for the legacy-vs-modern endpoint split.
