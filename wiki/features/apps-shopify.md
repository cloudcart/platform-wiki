# Shopify Importer

## Purpose

**Shopify Importer** is a one-way migration tool from a **Shopify** store to CloudCart. The merchant configures credentials for their Shopify store; the app pulls in products and imports them into the merchant's CloudCart catalog.

Compared to the more comprehensive [[apps-magento]] importer, Shopify is currently a **minimal flow** per the available translations: products only, no documented customer / category / variant migration. (Verify whether the actual implementation goes deeper than the lang file's brief description.)

## Where to find it

Sidebar → Apps → install → **Shopify**.

The route is `/admin/apps/shopify`. The modern Vue route currently renders a placeholder; the actual flow uses legacy Smarty / pre-Vue components.

### Install (Header: "Shopify installation")
The merchant installs the app from the App Store.

Description (`info.title`): "Shopify". Capabilities (`title.able_to` + `info.install`):
- *"With Shopify you will be able to: import products from Shopify in your online shop."*

### Configure (Header: "Shopify settings")
Help text: *"Set up the settings below in order to configure correctly your online store with Shopify."*

### What the merchant CANNOT do here
- Migrate orders (per lang file, only products are documented).
- Migrate customers (not in scope according to current strings).
- Run a TWO-WAY sync (one-way import only).

## Business rules

### Import-only model
Like [[apps-magento]], Shopify Importer is one-way. After import, CloudCart is the master; Shopify is not modified.

### Limited scope per documentation
Current lang strings suggest products-only import (no customers / orders / categories). May expand in future.

### Permission
Standard apps permission scope.

## How it works (verified against backend)

### CSV upload — not an API connection to Shopify

The Shopify importer is a **file upload**, not an API integration. The merchant exports their catalog from Shopify as the standard CSV file (Products → Export from the Shopify admin), then uploads it here. There is no Shopify store URL, API key, or access token field — that whole credential model does not exist for this app. The settings form has exactly two inputs: an **Active** toggle and a **File** upload (the file field reuses the WooCommerce label).

### CSV columns mapped by index — standard Shopify export format

The importer reads CSV cells by hardcoded column position (column 13 = SKU, 22 = barcode, 18 = price, 46 = quantity, 23 = image URL, columns 7/8 = variant option name/value). This is the column order Shopify ships in its standard product export — files generated by third-party Shopify export plugins with reordered columns will not import correctly.

### Variants — multi-row CSV records grouped by product handle

Each row in Shopify's CSV is one variant of a product; rows with the same product Handle (column 0) belong to the same product. The importer groups them and builds one CloudCart product with multiple variants. Each variant carries its own SKU / barcode / price / quantity / image.

### Images downloaded into CloudCart media

Image URLs from the CSV (column 23) are fetched and uploaded into CloudCart's own media storage. The merchant's Shopify storefront can be taken offline after import without breaking CloudCart product images.

### Background import via queue — file lives on S3

The uploaded CSV is stored on S3 under `{site_id}/imports/shopify/{timestamp}.csv`. A `shopify_products` queue task streams the file back from S3, parses it, and dispatches batches of 20 product IDs through the generic importer queue. The merchant can navigate away — progress is tracked in settings (`total`, `complete`, `msg`).

### Orphan S3 cleanup on dispatch failure

If the queue task dispatch throws, the uploaded CSV is deleted from S3 to avoid orphan blobs. So failed installs do not leak storage.

### No order or customer import path

The importer creates only product records. Orders and customers from Shopify are NOT migrated — the merchant has to handle order history separately and customers re-register on CloudCart.

### Multi-store — one CSV file at a time

Per the single `csv_file` field: each upload imports one Shopify store's export. Shopify Plus merchants with multiple stores would have to upload each store's CSV separately. There is no built-in store-selector.

### Modern Vue screen is a placeholder — Smarty templates drive the actual flow

The modern Vue route is empty — the upload form is rendered by legacy Smarty templates. The Vue route is wired but empty, pending future migration.

### S3 storage for the uploaded CSV — per-site, timestamp-keyed

The uploaded CSV is stored at `{site_id}/imports/shopify/{timestamp}.csv` on S3. The `shopify_products` queue task reads it back via the `s3` disk and deletes it after processing. This avoids local disk pressure for large catalogs and works across multiple worker servers.

### Pre-upload progress reset wipes prior state

Each new upload first clears any prior progress (completed / complete / total / msg / info settings) AND deletes any existing import records (`records` / `failed_records` on the app). So an in-progress import cannot be restarted — the merchant has to wait for the previous one to finish or accept losing it.
