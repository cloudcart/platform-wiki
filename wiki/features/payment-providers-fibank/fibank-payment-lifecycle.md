# Fibank — Payment lifecycle

> Part of [[payment-providers-fibank]]. See the hub for the other aspects (setup & certificates, refund / capture).

## Purpose

This page covers what happens when a customer pays with Fibank: the redirect to Fibank's hosted Ecomm page, the mandatory 3-D Secure challenge, the return callback, and the periodic status sync that reconciles missed returns. It also documents the **Return URL** the merchant must register with Fibank and the order-ID format CloudCart sends as the transaction description.

## Where to find it

Sidebar → **Payment Providers** → **Fibank**. Route: `/admin/payment-providers/fibank`. The Return URL is shown read-only on the settings page; the rest of the lifecycle runs at storefront checkout, not in the admin.

## What the merchant can do here

- **Copy the Return URL** the platform exposes and give it to Fibank when registering the terminal.
- **Observe payment status** on the order — driven by Fibank's `RESULT` field (see [[fibank-refund-capture]] for the status mapping).
- Nothing about the redirect / 3DS flow itself is merchant-configurable — it's Fibank policy.

## Settings & fields

| Field / Control | What it does | Default | Validation / notes |
|-----------------|--------------|---------|--------------------|
| **Return URL** | Read-only display of the URL the merchant tells Fibank to send the customer back to. | `<cc_payments_domain>/return/provider/fibank` | Copy-paste into Fibank's terminal configuration. |
| **3-D Secure** | Mandatory; not exposed as a toggle. | Always on | Enforced on Fibank's hosted page. |

## Business rules

### Payment flow (purchase → redirect → return → sync)

1. **Purchase** — the platform calls Fibank's Ecomm `registerOrder` operation over XML/HTTPS with mutual TLS, sending the merchant's `orderId`, amount (in minor units), `currency` (numeric ISO from configuration — 975 or 978), description (`Order #<order_id> / <site_url>`), and `returnUrl`. Fibank responds with a `formUrl` and a `TRANSACTION_ID`.
2. **Redirect** — the customer is sent to Fibank's `formUrl` to enter card details and complete 3DS on the bank's hosted page.
3. **Return** — Fibank POSTs the customer back to `<cc_payments_domain>/return/provider/fibank?trans_id=<id>`. The platform reads the final `RESULT` (via `getOrderStatusExtended`) and updates the payment status.
4. **Sync** — Fibank's Ecomm protocol has **no separate webhook / IPN URL**. To reconcile missed returns (customer closed the tab, network drop), the platform runs periodic `sync` calls (`checkTransactionStatus` → `getOrderStatusExtended`) against the stored `TRANSACTION_ID`. The `RESULT` is mapped per the table in [[fibank-refund-capture]].

### 3-D Secure is mandatory

Every Fibank charge goes through the bank's 3DS flow on Fibank's hosted Ecomm payment page. The merchant **cannot disable** 3DS — it's Fibank policy. The customer is redirected away from the storefront to Fibank's page, enters card details, completes 3DS if their issuer challenges, and is redirected back with the `trans_id` of the transaction.

### Card networks supported

Visa, Mastercard, Maestro. (Amex / JCB / Diners are not typically activated on Fibank Ecomm terminals — confirm with Fibank for the specific merchant's contract.)

### Return URL the merchant gives Fibank

```
<cc_payments_domain>/return/provider/fibank
```

Shown read-only on the settings page as **Return URL**. The merchant tells Fibank to set this as the return URL on the terminal configuration. Fibank POSTs the customer back with `trans_id=<transaction_id>` after payment completes.

### Order ID / transaction description format

The platform sends `Order #<order_id> / <site_url>` as the transaction description — using whichever Order ID display the merchant configured (sequential ID or `increment_hash`). There is no special numeric-only constraint — Fibank's description field is a long string. The transaction-side reference (`TRANSACTION_ID`) is generated by Fibank and stored as the platform's `provider_reference_id`.

### Currency sent on every request

The configured `currency_test` / `currency_live` (975 or 978) is sent verbatim on `registerOrder`. The platform does **not** auto-convert if the storefront currency differs — see [[fibank-setup-certificates]] for the one-currency-per-terminal rule and how to align store currency.

### Connection timeout

The Fibank Ecomm endpoint can be slow — the platform uses a **5-second connection timeout** on every API call to fail fast if the bank is unresponsive. SSL verification is disabled (`ssl_verify = false`) — the PKCS#12 mutual-TLS auth is sufficient.
