# Emails — Auto-DNS + Instructions modal

## Purpose

When the merchant activates CloudCart's hosted email service for a domain (i.e., creates the first mailbox on that domain), the platform **automatically writes** four DNS records into the domain's Cloudflare zone: MX, SPF, DMARC, and DKIM. The **Instructions** modal (opened per-row) then shows the live DKIM public key + selector and the IMAP / SMTP / POP3 connection details the merchant needs to configure external mail clients.

This page covers what gets auto-written, the per-domain DKIM selector rule, the Cloudflare-only constraint, and the full contents of the Instructions modal.

## Where to find it

Two surfaces:

- **Auto-DNS write** runs automatically on activation of the **first mailbox per domain**. No explicit UI trigger — the records appear in the [[settings-domains]] DNS modal after the activation completes.
- **Instructions modal**: Settings → Emails → per-row **Instructions** action. Opens a standard b-modal rendered by `InstructionsPreview.vue`. Body fetches live data from `/admin/api/core/settings/emails/instructions/<account_id>/<domain_id>`.

## What the merchant can do here

### View setup instructions for an external mail client

Per-row **Instructions** modal contains a read-only display of the mailbox's connection details (fetched live so the DKIM key and server hostnames are always current, not snapshotted):

- Email address.
- DKIM public key (long string).
- DKIM key selector.
- IMAP / SMTP / POP3 hostnames + ports.
- Recommended TLS settings.

The merchant copies these values into Outlook, Gmail, Apple Mail, mobile clients, etc. to send / receive mail for the mailbox through external clients.

### View the auto-written DNS records

Auto-written records appear in [[settings-domains]] → per-row **Manage DNS** modal after mailbox activation. The merchant should verify they're present (and not accidentally edited / removed later) for outgoing mail to authenticate properly against modern receiving mail servers (Gmail, Outlook, etc.).

## Settings & fields

### Instructions modal contents

| Item | What it provides |
|------|------------------|
| **Email address** | The mailbox's full address (e.g., `support@mystore.bg`). |
| **DKIM public key** | For external mail verifiers (delivered automatically to the domain's DNS — see below). |
| **DKIM key selector** | Pair-match for the DKIM record. **The domain name itself** is the selector (`<domain>._domainkey`), not a generic platform-wide selector. |
| **IMAP hostname + port** | For configuring inbound (read) in external clients. |
| **SMTP hostname + port** | For configuring outbound (send) in external clients. |
| **POP3 hostname + port** | Alternative inbound protocol. |
| **TLS settings** | Recommended security settings for the external client. |

### Auto-written DNS records (per domain, on first mailbox activation)

| Record type | Name | Value | Purpose |
|---|---|---|---|
| **MX** | `<domain>` | Points to `mail.cloudcart.com` | Tells external mail servers where to deliver mail for `@thisdomain`. |
| **TXT (SPF)** | `<domain>` | `v=spf1 mx ~all` | Allows mail sent from the MX host (CloudCart's mail server) to pass SPF checks; other origins get soft-fail. |
| **TXT (DMARC)** | `_dmarc.<domain>` | `v=DMARC1; p=none; pct=100; rua=mailto:dmarc-reports@<domain>` | DMARC monitoring (no rejection policy by default; just reporting). |
| **TXT (DKIM)** | `<domain>._domainkey` | Generated DKIM public key (selector auto-generated by the platform) | Signs outgoing mail so receivers can cryptographically verify origin. |

## Business rules

### DKIM / SPF / DMARC / MX are written through Cloudflare (not Name.com)

The DNS records (MX, TXT-DMARC, TXT-SPF, TXT-DKIM) are written through the **Cloudflare DNS API** on the host's Cloudflare zone — not Name.com (a previously-used registrar still referenced in commented-out code).

The Cloudflare-zone-id of the host is the required handle. **If the host isn't on Cloudflare** (e.g., the merchant has external DNS), the auto-DNS writes are silently skipped. The merchant has to add the records manually in their own DNS provider in that case.

### DKIM selector is per-domain, not platform-wide

The DKIM record selector is **the domain name itself** (`<domain>._domainkey`), not a generic platform-wide selector. So each mailbox-enabled domain has its own DKIM key, isolated from other stores' domains.

This means rotating the DKIM key on one domain does not affect any other store or domain.

### Auto-DNS fires only on first mailbox per domain

When the merchant creates a mailbox and the Modoboa domain doesn't yet exist, the activation flow writes the four DNS records. Subsequent mailbox creations on the same domain reuse the existing records (no duplication).

### Auto-DNS records survive last-mailbox deletion

If the merchant deletes the last mailbox on a domain, the MX / SPF / DMARC / DKIM records stay in the Cloudflare zone. They must be removed manually from the [[settings-domains]] DNS modal if the merchant wants to remove them entirely. See [[settings-emails-management]] for the delete-does-not-cleanup-DNS rule.

### Instructions endpoint pulls live DKIM key from Modoboa

The `instructions/{id}/{domain_id}` endpoint fetches the live DKIM public key + selector from Modoboa's domain record (so the keys shown in the Instructions modal are always current, not a snapshot). The endpoint also looks up the matching domain `host` from CloudCart's domain table to confirm the modal is showing the right mailbox.

If the DKIM key has been rotated by the platform, the Instructions modal will immediately reflect the new key on next open — the merchant should re-copy the value into any external verifiers that store a pinned key.

### Verify records are present before troubleshooting deliverability

Common deliverability complaint: *"My mail from `support@mystore.bg` lands in spam at Gmail."* First check: open [[settings-domains]] → per-row **Manage DNS** for the affected domain → verify MX / SPF / DMARC / DKIM are present and have the expected values. If they're missing (e.g., merchant edited them out), re-creating them manually or re-activating the email service restores deliverability.

If the domain isn't on Cloudflare (auto-DNS was skipped at activation), the merchant must add all four records in their own DNS provider matching the values in the table above.
