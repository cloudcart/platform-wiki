# Api keys — Create / Edit modal

> Part of [[settings-api-keys]]. See the hub for related aspects (table, rate limits, delete protection, security).

## Purpose

The right-side slide-out modal that opens when the merchant clicks **+ Add Api key** in the page header (Create mode) or clicks any key row's Name (Edit mode). Covers the form fields, validation rules, button behaviour, the misleading-but-intentional "Generate" label in Edit mode, and what is deliberately NOT in the modal (no regenerate, no scope picker, no "show only once" hiding).

## Where to find it

Triggered from [[settings-api-keys-overview]]:

- Sidebar → Settings → Api keys → **+ Add Api key** (Create mode).
- Sidebar → Settings → Api keys → click any row's **Name** column (Edit mode).

The modal uses the `modal-right` class, size `lg`. Header bar splits 1/3 (title) + 2/3 (Cancel + Generate buttons inline). No footer separator — the action buttons live in the header.

## What the merchant can do here

- Enter a **Name** for the key (Create + Edit).
- Enter / edit a **Description** (Create + Edit).
- In Edit mode, see the full **API key** value as a read-only field (so it can be copied from inside the modal).
- Click **Generate** to submit (Create or Edit).
- Click **Cancel** to close without saving (disabled while the mutation is in flight).

## Settings & fields

| Field | Control | Mode | Behaviour |
|-------|---------|------|-----------|
| **Name** (`name`) | `CcInput` with column-style label + tooltip | Create + Edit | Required (Zod min 1 with message *"Name is required"*). Tooltip: *"Type the name of this API key. It can be anything, for example: Zapier or Google"*. The form does not pre-validate length / uniqueness; submit failure surfaces server-side errors via the error store. |
| **API key** (`key`) | `CcInput` with `readonly=true` | **Edit only** | The full 64-char value shown read-only so the merchant can see + copy from inside the modal. Tooltip: *"Please name the API key you are creating. The name and description are for internal use. They will help you recognize the API keys for different applications."* Hidden in Create mode (the value doesn't exist yet). |
| **Description** (`description`) | `CcTextarea` | Create + Edit | Optional free-text note. Server caps at 191 chars. |

### Footer

- **Cancel** — closes without saving. Disabled while the mutation is in flight.
- **Generate** — primary action. Shows a loading spinner during the mutation. **The label stays "Generate" in BOTH Create and Edit modes** — see Business rules below.

## Business rules

### Server-side Name validation: required + 50-char + unique

The backend validates the **Name** field with three rules:

- `required` (matches Zod min 1).
- `max:50` — the Zod schema does not enforce this client-side, so typing more than 50 chars passes the form but is rejected by the server with a 422 validation error.
- `unique:api_keys,name` — **Name MUST be unique across all of the store's API keys.** Two keys with the same name fail with a validation error; editing a key to the same name as another existing key also fails. Enforced server-side only; the create modal does not pre-validate, so the merchant sees the error only after clicking Generate.

The **Description** field is capped at 191 characters server-side.

### Key generation is server-side and one-shot

The merchant types only a Name and Description. The actual key value is generated by the platform at create time as a 64-character random uppercase string. The merchant cannot supply or choose the value. To "rotate" a key the merchant must:

1. Create a new key (with a clear name like `<old-name>-2026-05`).
2. Update the consuming integration.
3. Verify the integration works.
4. Delete or deactivate the old key.

There is no in-place rotation — the immutability is enforced at the model layer too. See [[settings-api-keys-security]].

### The "Generate" button label in Edit mode IS the actual UI text

Confirmed against the current code: clicking **Generate** in Edit mode triggers a PATCH update that mutates ONLY `name` + `description` — the key value is NOT regenerated, and the model layer would revert any change anyway (see [[settings-api-keys-security]]). The "Generate" label in Edit mode is misleading copy; the button effectively performs a save. To actually generate a new key value the merchant must delete the row and create a new one.

On Edit-mode success → toast *"Saved successfully"*, modal closes, the row in the table is mutated in-place (no full refetch).

### What is NOT in this modal

- **No "regenerate key value" action.** To rotate, delete the row and create a new one.
- **No per-key scope / endpoint restriction.** Any active key on the store can hit any endpoint the plan permits.
- **No "show full key value only once" pattern.** The 64-character value stays visible (and copyable) from the Edit modal forever. See [[settings-api-keys-security]] for why this matters.
- **No "test API key" action.** The merchant validates a key by making an actual API call from their integration.
